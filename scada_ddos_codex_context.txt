SCADA DDoS / IDS TESTBED — PROJECT CONTEXT FOR CODEX

PURPOSE This project supports research work for a paper titled:
“Cybersecurity of Energy-Sector SCADA Systems: Attack Vectors and
Defense-in-Depth Mitigations.”

I was asked by Dr. Kaur, the first-listed author, to work specifically
on the DDoS portion of the research. The intention is to add
experimental/local-trial results related to DDoS attacks and DDoS
mitigation rather than leaving that portion of the paper purely
conceptual.

The work should be a controlled, local cybersecurity research/test
environment. The target systems are fake/simulated systems under my
control. I want to be able to “DDoS myself” inside an isolated virtual
network and collect quantitative results. This is not intended to target
external systems.

CORE RESEARCH INTENTION I want to construct a local SCADA-oriented
security testbed in which I can:

-   Create simulated/fake SCADA network devices and endpoints.
-   Generate controlled DDoS-style traffic against those simulated
    endpoints.
-   Define multiple attack profiles.
-   Configure parameters such as:
    -   attack type/profile
    -   burst rate
    -   attack duration
    -   wait/pause period between bursts
-   Observe the attack in real time.
-   Run an IDS against the traffic.
-   Measure and display things such as:
    -   connection rate
    -   protocol/application frame rate
    -   rejected/blocked traffic
    -   allowed traffic
    -   malformed traffic
    -   blocked connections
    -   attack/traffic rates over time
-   Plot attack activity and IDS observations on graphs.
-   Enable/disable mitigation.
-   Experiment with different mitigation mechanisms and parameters.
-   Compare mitigated and unmitigated trials.
-   Save quantitative results that can ultimately be used in an academic
    paper.

SCADA / PROTOCOL CONTEXT The paper is specifically concerned with
energy-sector SCADA cybersecurity.

The paper discusses DDoS as an availability attack capable of disrupting
telemetry, delaying operator commands, exhausting constrained PLC/RTU
resources, and reducing situational awareness.

The paper discusses industrial protocols including: - Modbus/TCP -
DNP3 - IEC 60870-5-104 - IEC 61850 GOOSE

A particularly relevant reference/example is an existing-looking testbed
shown by another paper author. Its UI is titled:

“IEC 60870-5-104 Security Testbed — DDoS Simulation & IDS”

The screenshot appears to be a custom locally hosted web application
(127.0.0.1:5000), rather than necessarily an off-the-shelf program.

The example UI contains:

ATTACK CONTROL — TOOLS → DDOS SIMULATION - Attack profile selector -
Example profile: “APDU flood (I/U/S frames)” - Burst rate - Duration
(minutes) - Wait period (seconds) - Start/Stop controls - IDS toggle -
Mitigation toggle

DEFENSE-IN-DEPTH MITIGATION GATEWAY - Frames allowed - Frames blocked
(rate) - Frames blocked (malformed) - Connections blocked

It also describes controls such as: - source allowlist / default-deny -
per-source connection threshold - per-connection frame rate limit /
token bucket - protocol-aware inspection

IDS/status indicators shown include: - Connection rate - STARTDT rate -
APDU rate - Malformed rate - severity/status such as GREEN/YELLOW

There is also a rolling-window graph showing these attack/control-plane
signals over time.

I want to make something broadly like this: a real test
harness/dashboard backed by our own isolated virtual SCADA network,
attack generation, IDS measurements, and mitigation controls.
